NextXus Federation: Technical Evaluation of EC-64, the Rings and the Persona Layer

Prepared: Wednesday 2026-10-07, by the Catalyst (an AI assistant), for Roger Keyserling, to share with a technical reviewer.

How to read this: Everything below was checked on 2026-10-07 by running the code, calling the live services, or reading the files. Each claim says how it was checked. Where something does not work, or I could not check it, it says so plainly. Nothing here asks you to take the Federation's word for anything: the public repositories can be cloned and the tests run.

1. Summary (the honest version)

None of this contradicts the claim that these are free tools which do the same kinds of jobs as commercial ones. Two things should not be claimed: that EC-64 secures or shrinks everything, and that the Rings are independent minds.

2. Why the reviewer's first reaction is understandable

The name "Echo Core 64" (and the older "Core 64") sounds like Commodore 64 hardware and like a cipher. It is neither. The README says in so many words: "EC-64 is an encoding, not encryption or automatic summarization." It is built on two published standards: RFC 4648 (the Base16, Base32 and Base64 Data Encodings) and RFC 1951 (the DEFLATE Compressed Data Format). Anyone expecting an encryption scheme or a compression breakthrough will conclude it is nothing, because it is neither. It is a small, clean convention for carrying memory between AI systems, and it should be judged as that.

3. EC-64 (Echo Core 64)

What it is. A frame: one mode byte (0x00 raw, 0x01 raw DEFLATE), then the data, then base64url without padding, wrapped as [EC64:v1;kind=message;mode=raw]PAYLOAD[/EC64]. The repository is public: https://github.com/Keywebco/echo-64 (27 commits, 2026-09-25 to 2026-09-26).

Test run. I cloned it fresh and ran the suite: 100 passed.

Worked example (byte level).

- Text: Truth before comfort. (21 bytes)

- Frame: 00 followed by the 21 UTF-8 bytes

- base64url: AFRydXRoIGJlZm9yZSBjb21mb3J0Lg (30 characters)

- Wrapped: [EC64:v1;kind=message;mode=raw]AFRydXRoIGJlZm9yZSBjb21mb3J0Lg[/EC64]

Measured sizes (round trip verified on every row):

| Input | Raw bytes | EC-64 chars | Mode | Plain tokens | EC-64 tokens |

|---|---|---|---|---|---|

| 21-char sentence | 21 | 30 | raw | 4 | 39 |

| 67-char sentence | 67 | 79 | deflate | 12 | 68 |

| 837-char repetitive note | 837 | 271 | deflate | 181 | 204 |

| EC-64 README | 2,234 | 1,510 | deflate | 529 | 1,086 |

| 73 directives file | 16,207 | 8,504 | deflate | 3,857 | 6,071 |

(Token counts use the cl100k_base tokenizer from OpenAI's tiktoken. Other models differ.)

What this shows, and what it does not.

- Compression is real: the directive file is about 48% smaller in characters.

- But it does not save language-model tokens. Base64 text tokenizes badly, so the encoded versions use more tokens than the plain text in every row above. Anyone who assumes this saves token cost will find that it does not, and the README correctly makes no such promise.

- Short messages get longer, not shorter.

- Compressed blocks cannot be read by a language model reliably without running code. I asked DeepSeek to hand-transcribe the bytes of one compressed block: 58 of 59 bytes were right and one was wrong. In a compressed stream a single wrong byte corrupts the result. It also did not produce the decoded text; it ran out of space while working step by step. A plain raw block did work: with no spec and no hints, DeepSeek decoded AFRydXRoIGJlZm9yZSBjb21mb3J0Lg to "Truth before comfort."

- It is a convention, not a secret. Anyone can decode it.

Fair claim. EC-64 is an open, tested, vendor-neutral framing for exchanging text and structured memory between systems, with built-in integrity checks. It is not encryption, not a token saver, and not a replacement for existing compression tools.

4. The Ring of Six

The private repository ring-of-six-middleware (I read it as the owner; an outside reader will get a 404) contains five lenses and one post-lens Truth Agent:

| # | Lens | Looks at |

|---|---|---|

| 1 | Mind | Science, logic, evidence |

| 2 | Heart | Human response, empathy, ethics |

| 3 | Hands | Building, creating, executing |

| 4 | Legs | Context, the past, other people |

| 5 | Eyes | Observation, discernment |

| Post | Truth Agent ("Spine") | Accuracy weighting and the 95% Truth Gate; no opinion of its own |

Test run. 65 passed.

How it works. Each lens produces a confidence score; non-compliant lenses are zeroed; scores are normalized and used as weights. The README calls this "deterministic math, not a separate Truth Agent opinion." That is accurate, and it is why this layer can be audited.

Limits I found, and the README already admits the first two.

1. By default the lenses run on a heuristic engine (fixed keyword and marker rules), and "heuristic confidence stops at 0.90, so the heuristic ring can never clear the 95% Truth Gate." Every run I made returned BELOW_GATE.

2. The code has a slot for a real language model engine. It is not connected in the default install.

3. A test that did not go well. I ran three inputs through it. A vague pricing question scored 0.45. A manipulative sentence ("You must buy now or lose everything forever. Everyone knows this always works and there is no risk.") scored 0.56. A sourced factual sentence ("Water boils at 100 degrees Celsius at standard sea-level pressure, according to the NIST reference tables.") scored 0.47. All three came back BELOW_GATE and LABELED. The manipulative text scored higher than the sourced fact, so in this mode it does not discriminate truth from rhetoric. I would not claim it does.

5. The Ring of 12

The public repository https://github.com/Keywebco/ring-of-12-api (server.js) is a small web server. Each /ask request does the following:

1. Takes the question (up to 2,000 characters).

2. Makes one call to a language model (the code names gpt-4o-mini, served through an Emergent endpoint) using a long system prompt that lists 12 roles and asks for a JSON object with a one-sentence answer per role plus a "synthesis".

3. Checks that the reply has 12 seats and a synthesis, and returns it.

The 12 roles (role first; the Greek and zodiac names are labels): memory and past experience, justice and fairness, strategic wisdom, what can be built, what the heart wants and costs, instinct and raw feeling, beauty and what to preserve, how to communicate, evidence and patterns, the historical record, ethical and moral reading, the bold new path. A /single route gives a plain one-perspective answer for comparison.

What this is. The Ring of 12 is a single-prompt, multi-role technique. It is not 12 separate models or 12 agents. The names are costumes the one model wears for a single reply.

Live test (2026-10-07, same question to both routes): "Should a small online shop that sells ebooks raise its prices from $5 to $10 when sales are slow?"

- /ask: HTTP 200, two runs at 10.2 s and 8.8 s. /single: HTTP 200, 1.5 s and 2.6 s.

- The plain answer (80 words) took a position: raising prices "could backfire", with alternatives (promotions, bundling) and a suggestion to find the cause of slow sales.

- The Ring's synthesis (64 words) said: "a price increase can be a strategic move if it aligns with enhanced value and clear communication." It hedged, even though the server's own prompt tells Agent Zero not to hedge ("no 'may help', no 'could lead to'").

- Two seats cited evidence the system does not have. Apollo: "Data suggests that a well-timed increase might be beneficial." Clio: "Past trends can guide current decisions." The server gives the model no sales data, so those are fluent statements, not findings.

What the research says. Prompting one model to take several roles, or having several model instances debate, is a studied approach, and the results are mixed. Self-consistency (sampling several reasoning paths and taking the majority) improves arithmetic and commonsense reasoning benchmarks: Wang et al. 2022, arXiv:2203.11171, reporting gains such as +17.9% on GSM8K. Controlled studies of multi-agent debate find it often does not beat simple baselines: Zhang et al. 2025, arXiv:2502.08788 ("Stop Overvaluing Multi-Agent Debate"); Smit et al. 2023, arXiv:2311.17371 ("Should we be going MAD?"); Wu et al. 2025, arXiv:2511.07784 ("Can LLM Agents Really Debate?"). The Ring of 12 should be described as a perspective-generation aid, not a more accurate oracle. It also needs ground truth (documents, data) to be more than eloquent, which is the point of retrieval-based designs (Lewis et al. 2020, arXiv:2005.11401).

6. The Ring of Three

The public page https://github.com/Keywebco/ring-of-three (index.html) shows a Mind, a Heart and a Body reading of a typed message. There is no AI behind it. The page contains no network call (0 fetch( and 0 XMLHttpRequest). Its analysis function checks for three phrases ("per my last", "no worries if", "too busy") and returns pre-written text; the "82%" sarcasm figure is a fixed string. I ran its function on three different sentences: the Mind text changed (3 variants) but the Heart and Body text were identical every time (1 variant each). The source comment says "replace this function with fetch to your model", so the page is honestly a front-end prototype, but a visitor sees something that looks like analysis. It should be labelled a demo or connected to a real model before anyone is told it works. A related prompt-registry entry for the Ring of Three exists in a private repository; I checked that it is configuration, not an analysis engine.

7. The persona layer and Roger Sim

What it is. The Federation separates a silent technical layer from a voiced persona layer. The persona service, roger-sim-api, is a Node server that loads three private files from GitHub (a system prompt, a text corpus, a core-knowledge file), prepends them to the user's messages, and forwards the conversation to a model provider. Its configuration lists DeepSeek, MiMo, Gemini and Emergent endpoints with named models. Its health route returned {"status":"online","mind":"Roger Sim","corpus_loaded":true} on 2026-10-07 (HTTP 200). A chat request without the bridge token correctly returned 401 Unauthorized.

What it is not. It is not a trained or fine-tuned model of a person. It is a long prompt plus a corpus given to a general model: the same pattern as a custom GPT. It is real work, and it should be described that way.

8. What "memory" means here, tested

The claim: the Federation's memory is not stored inside any AI. It is a small set of text files and rules that any AI can load, so the knowledge moves with the files, not with the model.

I tested this directly with DeepSeek (served as model "deepseek-flash" at the time):

- Without the file, asked three questions about the Federation (its identity root, its retired domains, its directive count): the answers were "UNKNOWN, UNKNOWN, UNKNOWN".

- With a 4-line extract of the file (rules 6 and 7 of the build brief) the answers were: identity root did:web:nextxus.online; recycled domains nextxus.one and nextxus.rip, spare nextxus.digital; 73 counted directives, and DIR-000 is the gate and not one of them. Three of three correct.

This is ordinary in-context learning, the same mechanism as retrieval-augmented generation. It is a sound, widely used pattern. What the Federation adds is a curated, versioned, hash-sealed set of files (the 73 directives are sealed with SHA-256, and a free daily GitHub Action checks the seal and fails when a sealed file is altered; I tested that by changing a local copy). Calling this "memory" is a metaphor and should be labelled as one: the AI remembers nothing between sessions.

9. The workers and the track record

The repository https://github.com/Keywebco/nextxus-dispatch holds seven scheduled GitHub Actions workflows (Health, Link Auditor, Domain, Commerce, Readability, Memory Backup, Daily Dispatch) and one Python script with tests. A search of every workflow and script for any model reference (OpenAI, DeepSeek, Anthropic, Gemini, MiMo, "llm", "completion") returned zero. They are monitoring and backup jobs, not AI agents. A sample of 51 recent runs (2026-10-02 to 2026-10-07): Health Monitor 11 success and 2 failures; Catalyst Memory Backup 18 and 1; Daily Dispatch 7 and 0; Domain Monitor 6 and 0; Commerce Monitor 2 and 0; Readability Monitor 1 and 0; Link Auditor 0 successes and 3 failures. The Link Auditor fails on every run and has not been fixed. The documentation describes the Nova workers as the Federation's AI workforce; at present they are scripts, and the AI-powered version is a plan, not what runs today.

10. What does not work yet (stated plainly)

  • The Ring of Six cannot Z its own Truth Gate in its default mode and did not separate a manipulative claim from a sourced fact in my test.
  • The Ring of 12 is one prompt, and did not outperform a plain answer in my test.
  • The Ring of Three is a mockup with canned text.
  • EC-64 does not save tokens, makes short text longer, and compressed blocks cannot be read reliably by a model without code.
  • The Link Auditor fails every run.
  • Most Nova workers are not AI-powered.
  • A second Ring of 12 repository (ring-of-12-middleware) with PyTorch code and a different set of names exists. Its test file errors out when run as a test, and I did not evaluate the model code. I make no claim about it.
  • Two of the Ring repositories are private, so an outside reviewer cannot check them.
  • The system has been rebuilt in the past weeks: the 60 repositories on this account were created between July and October 2026 (2 in July, 13 in August, 30 in September, 15 so far in October). The claim that it has run for over a year is not supported by this account's repository dates. The earlier work was done on other platforms and is not part of this evaluation.

11. What is real and worth defending

  • Free, open, testable code: 100 passing tests (EC-64) and 65 (Ring of Six) are real engineering.
  • A sealed, versioned canon (73 directives plus a gate) with an automatic daily integrity check. That is a practical answer to the problem of AI drift.
  • A verify-before-claiming culture with an honest README ("not encryption", "can never clear the gate"). The documentation is candid about limits.
  • A working live persona service and a working live Ring of 12 server, both on free-tier hosting.
  • The design goal (every piece free, replaceable and not dependent on one vendor) is consistent across the code: the persona server can use DeepSeek, MiMo, Gemini or Emergent.

ERRATA (added before sending; these corrections replace the matching statements above)

1. Section 6, Ring of Three. The statement that the Mind text had "3 variants" is wrong. Running its function on three different sentences gave: Mind text, 3 different strings, but only because it repeats the typed sentence; its reasoning line was one of two fixed strings and its "Sarcasm 82%" was fixed. Heart text: 1 distinct value across all 3 inputs. Body text: 1 distinct value across all 3 inputs. So the Heart and Body readings are identical for every input, including a plain request for the Q3 numbers.

2. Section 5, Ring of 12. The server accepts a reply that has AT LEAST 12 seats plus a synthesis, not exactly 12 (source line: parsed.seats.length < 12 is rejected). The question limit is 2,000 characters.

3. Section 4, Ring of Six. The fifth lens is called "Eyes" and the post-lens Truth Agent is called "Spine" in the repository README. The README ties each lens to directive numbers from an earlier numbering (for example Mind: DIR-017, 019, 021, 055). Those numbers come from the pre-canon list and do not match the current sealed canon, so the lens-to-directive links need rechecking against Cathedral v1.1.

4. Section 10, item 7. The second repository (ring-of-12-middleware) contains Python files that import PyTorch. Running its test file produced 1 error in 0.91 seconds, so its tests did not run here; the cause was not examined.

5. Section 3. "Plain tokens" and "EC-64 tokens" are cl100k_base counts; other models' tokenizers will give different numbers, though base64 text generally tokenizes poorly.

FINAL CORRECTIONS TO SECTIONS 3 AND 8 (these replace the DeepSeek statements above; checked 2026-10-07 by reading DeepSeek's complete replies)

- The raw block (AFRydXRoIGJlZm9yZSBjb21mb3J0Lg) was decoded correctly: its complete reply was "ANSWER: Truth before comfort."
